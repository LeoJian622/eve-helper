# Knowledge - 功能模块流程资料库

本目录存放**功能模块级的技术流程文档**（如登录生命周期），目标是让开发者（含 AI 实例）快速理清一个模块的完整链路，而不必通读代码。

## 约定

1. **一个功能模块一份文档**。模块完成或重大变更时生成/更新；新功能模块交付时应同步产出对应文档。
2. **命名**：`<模块名>-lifecycle.md` 或 `<模块名>.md`（小写中划线），如 `login-lifecycle.md`、`market-orders.md`。
3. **内容以代码为准**：文档陈述的行为必须与当前实现一致；发现漂移时以代码为准并更新文档，过期章节标注而非删除历史设计意图。
4. **登记索引**：新建文档后在 `docs/INDEX.md` 工具文档表登记一行。

## 文档模板

参照 [login-lifecycle.md](./login-lifecycle.md) 的结构，新文档按需裁剪：

```markdown
# <模块名> 全生命周期流程

> 面向开发者：理清 <模块> 从 <入口> 到 <出口> 的完整链路。
> 关联代码集中在 <若干包路径>。

## 1. 总览
一句话说清模块采用的技术方案 + 一张全局流程图（ASCII 或 mermaid flowchart）。
若模块涉及多套易混淆的概念体系（如两套 token），用对照表区分。

## 2-N. 各阶段流程
按时间/调用顺序分节，每节包含：
- 端点 / 入口（HTTP method + path，或触发时机）
- 参与组件与调用链（类名.方法名）
- 分支：成功路径 / 失败路径
- **时序图**（mermaid sequenceDiagram，交互跨 3 个以上组件时必备）

## 数据与存储模型
涉及的表 / 缓存键 / 队列等：全景表（键、值、TTL、说明）+ 必要的关系图（mermaid flowchart）。

## 安全与设计要点
对策对照表：对策 | 位置（代码） | 目的。标注有意的偏离（如防枚举的统一措辞），防止后人当 bug「修复」。

## 关键代码文件索引
环节 -> 文件路径 的映射表。
```

## 撰写要点

- **标注"有意的偏离"**：代码里为安全/兼容做的反直觉决策（如 `code_challenge` 留空、统一错误码）必须写明动机，否则会被后人误改。
- **图优先于文字**：跨组件交互用 mermaid 时序图；数据关联用 flowchart；简单流程用文字即可，不为画图而画图。
- **含调用方缺口要如实说明**：如某公共方法暂无调用方，写明（"前端自行拼接或待接线"），避免读者误以为链路断裂是文档遗漏。
