# Feature Specification: Wallet Overview（钱包总览）

**Feature Branch**: `012-wallet-overview`
**Created**: 2026-08-19
**Status**: Draft
**Input**: User description: "APP调用时需要一个钱包根据角色或军团的总览数据。基于已同步的钱包流水(wallet_journal)在数据库侧聚合,提供按人物或军团维度的汇总数据接口,只读不触发 ESI 同步。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看人物钱包总览 (Priority: P1)

作为 EVE 玩家，我希望进入某个人物的钱包总览页时，看到该人物的钱包摘要：当前余额、区间收入/支出/净额、流水条数、数据新鲜度（最后同步时间），以及按收支类别拆分的分布和按时间线的收支趋势，**以便**快速掌握该人物的钱包健康状况与资金流向。

**Why this priority**: 人物总览是最小可交付单片——数据源（人物 journal，division=0）在 009/010 已就绪，聚合语义清晰，是总览的核心价值。

**Independent Test**: 可独立测试。对一个已同步钱包流水的人物，调用其总览接口能返回当前余额、区间收支净额、类别分布与时间趋势；无权访问的人物被拒绝；从未同步的人物返回全零而非报错。

**Acceptance Scenarios**:

1. **Given** 某人物已同步过钱包流水，**When** 查看其钱包总览，**Then** 返回当前余额（等于该人物钱包最新流水记录的余额）、累计收入、累计支出、净额、流水条数与最后同步时间。
2. **Given** 指定了时间范围（如近 30 天）的人物总览，**When** 查看，**Then** 收入/支出/净额与类别分布按该范围聚合，趋势按时间线展示。
3. **Given** 当前用户**无权**访问某人物，**When** 请求其总览，**Then** 请求被拒绝，不返回任何数据。
4. **Given** 某人物从未同步过钱包流水，**When** 查看其总览，**Then** 返回零值摘要与空分布/空趋势（不报错）。
5. **Given** 按收支类别查看人物总览，**When** 查看类别分布，**Then** 返回各类别（refType）的收入、支出与笔数。

---

### User Story 2 - 查看军团钱包总览（全分账 + 分账分布）(Priority: P2)

作为军团负责人或管理员，我希望查看某军团的钱包总览时，看到军团整体的摘要（当前总额、区间收支净额、流水条数、数据新鲜度），并看到**按分账(division 1-7)展开的余额与收支分布**，**以便**对比军团各账目的资金余量。

**Why this priority**: 军团总览依赖 011 交付的 division 1-7 流水同步，其分账分布维度是军团侧特有价值，依赖已存在的军团流水数据。

**Independent Test**: 可独立测试。对一个已同步全分账流水的军团，调用其总览接口能返回整体摘要与按分账的余额/收支分布；无权访问的军团被拒绝；某分账无数据时该分账显示零而非报错。

**Acceptance Scenarios**:

1. **Given** 某军团已同步全分账钱包流水，**When** 查看其总览，**Then** 返回军团整体当前余额（各分账余额之和）、区间收入/支出/净额、流水条数与最后同步时间，以及按分账(1-7)的余额与收支分布。
2. **Given** 某军团某分账从未有流水，**When** 查看总览，**Then** 该分账在分布中显示为零值而非报错。
3. **Given** 当前用户**无权**访问某军团，**When** 请求其总览，**Then** 请求被拒绝，不返回任何数据。
4. **Given** 查看军团总览时未指定分账，**When** 查看，**Then** 返回全分账汇总 + 全分账分布。

---

### User Story 3 - 查看军团单分账钱包总览 (Priority: P3)

作为军团负责人或管理员，我希望查看军团总览时可选指定单个分账（division），**以便**聚焦查看某一个钱包账目的摘要与分布，而不是总是看全量。

**Why this priority**: 单分账聚焦是军团侧体验优化，依赖 011 的分账流水数据与 US2 的聚合能力，可复用同一套聚合逻辑。

**Independent Test**: 可独立测试。对某军团指定 division 调用总览，能返回该分账的摘要与分布；division 越界被拒绝。

**Acceptance Scenarios**:

1. **Given** 某军团已同步某分账流水，**When** 指定该分账查看总览，**Then** 返回该分账的当前余额、区间收支净额、类别分布与时间趋势（不含其它分账数据）。
2. **Given** 请求军团总览时指定了非法分账（如 0 或 8），**When** 请求，**Then** 请求被拒绝。

---

### Edge Cases

- **数据新鲜度**：总览数据新鲜度取决于最近一次同步；接口须返回最后同步时间戳，前端据此提示，不自动触发同步。
- **空数据**：从未同步或区间内无流水时，返回零值摘要与空分布/空趋势，而非报错。
- **归属权校验**：任何用户不得越权读取他人/其它军团的钱包总览。
- **时间范围**：未指定时间范围时聚合全量已同步流水；指定 start/end 或预设（近7天/30天/90天/今年/今天）时按范围聚合；start>end 或非法范围被拒绝。
- **分布/趋势条数**：refType 类别较多或时间刻度较多时，须控制返回条数上限，避免响应过大。
- **军团分账**：军团分账固定为 1-7；分账过滤仅对军团有意义，人物无分账概念。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许用户查询其**有权访问的人物**的钱包总览，基于该人物已同步的钱包流水聚合。
- **FR-002**: 系统 MUST 在人物总览中返回：当前余额、区间收入、区间支出、区间净额、流水条数、最后同步时间。
- **FR-003**: 系统 MUST 在人物总览中返回**按收支类别**（refType）的收入、支出与笔数分布。
- **FR-004**: 系统 MUST 在人物总览中返回**按时间线**（日/月刻度）的收入、支出与净额趋势。
- **FR-005**: 系统 MUST 允许用户查询其**有权访问的军团**的钱包总览，聚合该军团全分账流水。
- **FR-006**: 系统 MUST 在军团总览（未指定分账）中返回整体摘要 + **按分账(1-7)** 的余额与收支分布。
- **FR-007**: 系统 MUST 允许军团总览按**单个分账**过滤，返回该分账的摘要与分布。
- **FR-008**: 系统 MUST 支持可选时间范围：`start/end` 自定义区间或预设（近7天/30天/90天/今年/今天）；未指定则全量。
- **FR-009**: 系统 MUST 在总览响应中返回**最后同步时间**，且接口**只读**已同步数据、**不触发**任意同步。
- **FR-010**: 系统 MUST 对当前用户**无权访问**的人物或军团拒绝总览请求。
- **FR-011**: 系统 MUST 对非法入参（非法分账、start>end、非法范围）拒绝请求。
- **FR-012**: 系统 MUST 对空数据返回零值摘要与空分布/空趋势，不抛错。

### Key Entities *(include if feature involves data)*

- **WalletJournal（钱包流水）**: 聚合数据源。每行含带符号金额（正=收入、负=支出）、账户余额（该笔后的余额，最新一笔即当前余额）、日期、收支类别(refType)、所有者ID、分账(division，人物=0，军团=1-7)。
- **Owner（所有者）**: 人物或军团，是总览聚合的主体维度。
- **WalletOverview（钱包总览）**: 聚合产物，含主指标、类别分布、时间趋势，以及军团侧的分账分布。

## Success Criteria *(mandatory)*

### Performance Criteria

- **SC-001**: 人物/军团总览接口须在已同步数据集上快速返回，95 百分位响应时间在秒级以内（聚合查询，非逐行内存计算）。
- **SC-002**: 分账/类别/趋势分布须控制条数上限，单次响应数据量有界。

### Code Quality Criteria

- **SC-003**: 新代码单元测试覆盖率须达到 ≥80%。
- **SC-004**: 越权访问与非法入参安全路径须有测试覆盖。

### Measurable Outcomes

- **SC-005**: 对已同步钱包流水的人物/军团，用户能在总览一次调用中获得主指标、类别分布、时间趋势（及军团分账分布）。
- **SC-006**: 总览始终反映最近一次同步的数据，并在响应中明示该同步时间。
- **SC-007**: 无权访问或非法入参的请求一律被拒绝，不泄漏任何钱包数据。

## Assumptions

- **数据来源**：总览完全基于已同步入库的钱包流水聚合；用户需先通过现有同步接口同步数据，总览不负责同步。
- **当前余额口径**：某主体（人物 / 军团某分账）的当前余额取其钱包流水最新一笔的余额；军团未指定分账时总额为各分账余额之和。
- **收支口径**：流水金额为正视为收入、为负视为支出（取绝对值）、两者之和为净额。
- **刷新语义**：总览不触发 ESI 同步；新鲜度由返回的最后同步时间表达，前端据此提示"数据更新至 xx"。
- **时间粒度**：时间趋势默认按日刻度；数据跨度过大时可退化为月刻度（具体规则在实现方案确定）。
- **主体形态**：人物无分账概念；军团分账固定为 1-7。
- **复用现有能力**：归属鉴权（防 IDOR）与结果封装等既有机制直接复用，不重新发明。
