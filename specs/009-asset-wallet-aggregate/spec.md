# Feature Specification: Asset Multi-Role Aggregate & Wallet Journal

**Feature Branch**: `009-asset-wallet-aggregate`
**Created**: 2026-08-18
**Status**: Draft
**Input**: User description: "为 EVE Online 玩家提供两个前端可用角色数据模块：1) 角色资产多角色聚合查询——枚举当前登录用户所有角色，逐角色鉴权，返回按角色分组的资产汇总（数量/类型/价值），复用现有单角色资产链路；2) 钱包流水(Wallet Journal)补全——基于已实现的持久化/ESI 层，新增人物 journal ESI 端口、应用服务、控制器、domain VO。沿用现有模式：所有权鉴权防 IDOR、手动同步+幂等 upsert、规范分页。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看所有角色的资产汇总 (Priority: P1)

作为 EVE 玩家，我希望在一个页面看到我**所有已绑定角色**的资产概况（每个角色持有多少物品、大致总价值、有多少类目），这样登进系统就能一眼判断哪个角色的资产最值得关注，而不必逐一切换角色查看。

**Why this priority**: 这是「多角色聚合」的核心价值——把分散在各角色的信息聚合到一处看板，是玩家日常高频入口；复用既有资产链路，风险低、见效快。

**Independent Test**: 可独立测试。用户拥有多个已绑定且已同步过资产的角色时，调用聚合查询接口应返回按角色分组的资产汇总；无任何角色或未同步角色时返回空/零值而不报错。

**Acceptance Scenarios**:

1. **Given** 当前用户拥有 2 个已绑定且均已同步过资产的角色，**When** 请求聚合汇总，**Then** 返回按角色分组的结果，每个分组含角色标识、物品总件数、资产总价值、类目数，且只包含当前用户有权访问的角色。
2. **Given** 当前用户有 3 个角色其中 1 个从未同步过资产，**When** 请求汇总，**Then** 该未同步角色以空资产（0 件 / 0 价值）呈现，不影响其他角色结果返回。
3. **Given** 当前用户名下没有任何角色，**When** 请求汇总，**Then** 返回空列表而非错误。
4. **Given** 一个角色属于当前用户，另一个角色属于他人，**When** 请求聚合，**Then** 结果不得泄露无权访问角色的任何资产或身份信息。

---

### User Story 2 - 同步并分页查看单个角色的钱包流水 (Priority: P2)

作为 EVE 玩家，我希望只为某个角色手动发起钱包流水同步，然后分页查看其资金变动流水（每笔金额、变动后余额、时间、来源类型、说明），以便核对资金去向。

**Why this priority**: 钱包流水持久化/ESI 层已具备，本模块补齐对外能力（同步+查询）。独立成片交付，让前端可立即使用。

**Independent Test**: 可独立测试。对单个角色执行同步后能从数据库分页读取其流水；未同步时返回空而非报错；无权访问角色被拒绝。

**Acceptance Scenarios**:

1. **Given** 当前用户有权访问某角色，**When** 请求同步该角色钱包流水并成功，**Then** 系统从 ESI 拉取流水写入数据库并返回同步结果。
2. **Given** 已同步过的角色，**When** 再次同步，**Then** 不产生重复记录（幂等），且能增量拉取新增流水。
3. **Given** 已同步数据的角色，**When** 分页查询其钱包流水，**Then** 返回含总数与每笔（金额、变动后余额、时间、来源类型、说明）的分页结果，按时间倒序。
4. **Given** 当前用户**无权**访问某角色，**When** 请求同步或查询该角色流水，**Then** 请求被拒绝，不返回任何数据。
5. **Given** 某角色从未同步过钱包流水，**When** 查询，**Then** 返回空分页结果（可提示前端先同步），而非报错。

---

### Edge Cases

- 同步过程中 ESI 调用失败（网络异常 / 令牌失效 / 限流）：返回清晰错误，不写入半截数据；已存在流水不受影响。
- 多角色数据隔离：任何用户不得越权读到其他用户角色的资产或流水。
- 大角色流水量大：分页必须稳定，单页大小有限制。
- 同步重复触发（连续点同步）：不产生重复流水记录。
- 资产价值计算：基于现有资产数据可得的字段（数量 + 类型）求值，精度以现有字段为准。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许用户请求获取**当前登录用户所有已绑定角色**的资产汇总，每个角色分组包含：角色标识、资产物品总件数、资产总价值、资产类目数。
- **FR-002**: 系统 MUST 只返回当前用户有权访问的角色汇总；无权访问角色的资产及身份信息 MUST NOT 出现在结果中。
- **FR-003**: 对未同步过资产的角色，系统 MUST 以空资产（0 件 / 0 价值 / 0 类目）返回，MUST NOT 报错或阻断其他角色结果。
- **FR-004**: 用户无任何角色时，系统 MUST 返回空列表，MUST NOT 抛错。
- **FR-005**: 系统 MUST 允许用户对某个其有权访问的角色发起钱包流水同步，从外部数据源拉取并持久化。
- **FR-006**: 系统 MUST 允许用户分页查询某角色的钱包流水，结果 MUST 返回总数及每笔的金额、变动后余额、发生时间、来源类型、说明。
- **FR-007**: 钱包流水同步 MUST 幂等——重复同步不产生重复记录，且能增量拉取新增流水。
- **FR-008**: 系统 MUST 对角色归属强制鉴权——用户只能访问其自身或其所在军团拥有的角色数据；越权访问 MUST 被拒绝且不泄漏数据。
- **FR-009**: 对从未同步的角色执行流水查询，系统 MUST 返回空分页结果而非错误。
- **FR-010**: 同步失败时系统 MUST 返回清晰错误，MUST NOT 写入半截/脏数据。

### Key Entities *(include if feature involves data)*

- **角色（Character）**: EVE 游戏角色，与用户有绑定关系；是资产与钱包流水归属的主体，用户可经绑定关系访问多个角色的数据。
- **角色资产（Asset）**: 某角色名下的物品集合（单件或叠放），每件含物品类型、所在位置、数量、件数等；按角色归集可汇总成资产概况。
- **钱包流水（Wallet Journal）**: 某角色钱包发生的一笔资金变动记录，含金额、变动后余额、发生时间、来源类型、说明；按角色归属，随时间演进，可累加。

## Success Criteria *(mandatory)*

### Performance Criteria
- **SC-001**: 资产汇总接口在角色数量 ≤ 10 且各角色资产已落库时，响应时间 MUST ≤ 5 秒（95th percentile）。
- **SC-002**: 钱包流水分页查询单页请求 MUST ≤ 500ms（95th percentile）。
- **SC-003**: 外部数据源调用 MUST 具备超时与失败处理，不得因远端异常拖垮主流程或写入脏数据。

### Code Quality Criteria
- **SC-004**: 新增代码单元测试覆盖率 MUST ≥ 80%。
- **SC-005**: 集成测试 MUST 覆盖核心用户旅程（汇总、同步、分页、越权拒绝、空数据）。
- **SC-006**: 所有鉴权与授权流 MUST 有安全测试覆盖。

### Measurable Outcomes

- **SC-007**: 玩家能以单次请求查看全部角色的资产概览，替代逐角色多次操作（操作次数从「角色数」降为 1）。
- **SC-008**: 玩家能为其任一角色独立完成钱包流水同步并分页核对，重复同步不产生重复流水。
- **SC-009**: 任何用户在无权限/无数据/空角色表边界下操作，都不会看到越权数据或得到难以理解的错误。

## Assumptions

- 资产数据由现有同步能力产生（各角色需已通过既有同步入口拉取过资产），本特性不重新实现资产同步逻辑。
- 钱包流水数据取自 EVE ESI 官方接口，玩家需完成该角色授权（具备对应数据访问权限）才能同步。
- 资产「总价值」基于现有资产数据可得的物品数量与类型信息计算；精度以现有资产字段为准。
- 本特性范围 = 资产多角色聚合 + 人物钱包流水对外能力补全；**钱包交易（Wallet Transactions）不在本特性范围**，作为独立后续特性交付。
- 现有角色归属鉴权策略（含军团成员可访问本军团资源）继续沿用，不做扩展或放宽。
- 钱包流水仅按角色维度提供；军团维度流水在既有定时任务中处理，不在本特性改动。
- 技术栈遵循项目冻结版本（Java 17 / Spring Boot 3.5.14 / MyBatis Plus / Redis），不做任何升级或替换。
