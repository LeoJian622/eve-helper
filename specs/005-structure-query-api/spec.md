# Feature Specification: 建筑表只读查询接口

**Feature Branch**: `005-structure-query-api`  
**Created**: 2026-08-09  
**Status**: Draft  
**Input**: User description: "建筑表只读查询接口:1.主要信息展示接口(分页列表,支持名称模糊/状态筛选/燃料到期排序)2.详细信息接口(单建筑详情)3.燃料剩余展示接口(即将耗尽预警)4.启动服务展示接口(建筑服务状态,详情含+独立端点)5.其他功能:统计概览、按状态/缺油筛选、增强/解锚时间提醒。绝对不提供新增及编辑功能给用户;数据由现有定时任务从ESI同步入库,接口只读本地库。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 浏览军团建筑清单 (Priority: P1)

作为军团管理者,我想分页浏览我所属军团的所有建筑,看到建筑名称、类型、所在星系、当前状态和燃料到期时间,以便快速掌握建筑全貌并定位目标建筑。

**Why this priority**: 这是所有其他功能的基础入口;没有列表就无法定位单栋建筑,后续详情/预警/统计都依赖它。

**Independent Test**: 给定一个拥有若干建筑的军团,以该军团成员身份请求列表接口,可返回含名称/类型名/星系名/状态/燃料到期的分页结果。

**Acceptance Scenarios**:

1. **Given** 用户拥有军团 A 的建筑, **When** 以军团 A 身份请求建筑列表, **Then** 返回该军团全部建筑的分页数据
2. **Given** 用户不属于军团 B, **When** 请求军团 B 的建筑列表, **Then** 拒绝访问且不泄露军团 B 是否存在建筑
3. **Given** 建筑列表, **When** 按燃料到期升序排序, **Then** 燃料最快耗尽的建筑排在最前
4. **Given** 建筑列表, **When** 按状态筛选 "low_power", **Then** 仅返回该状态建筑

---

### User Story 2 - 查看建筑详情 (Priority: P1)

作为军团管理者,我想查看某栋建筑的完整信息,包括增强时间窗口、状态计时、解锚时间与已启用服务列表,以便了解建筑运行细节并做决策(补燃料、调整增强)。

**Why this priority**: 详情是运维决策的依据,与列表同为最高优先级的核心能力。

**Independent Test**: 给定建筑存在且属于当前军团,请求详情接口,可返回全部字段含已解析的服务列表。

**Acceptance Scenarios**:

1. **Given** 建筑 X 属于当前军团, **When** 请求其详情, **Then** 返回完整字段(含服务列表、增强时间、状态计时)
2. **Given** 建筑 Y 不属于当前军团, **When** 请求其详情, **Then** 拒绝访问且不泄露建筑存在性
3. **Given** 建筑的服务数据为空, **When** 请求详情, **Then** 服务列表返回空且不阻断详情展示

---

### User Story 3 - 燃料剩余预警 (Priority: P2)

作为军团管理者,我想查看未来若干小时内燃料即将耗尽的建筑清单及剩余时长,以便及时补燃料避免建筑离线。

**Why this priority**: 燃料耗尽会导致建筑服务中断,属重要预警,但定位依赖列表与详情,优先级次之。

**Independent Test**: 给定某建筑燃料将在 48 小时内耗尽,请求 72 小时预警窗口,可返回该建筑及剩余约 48 小时。

**Acceptance Scenarios**:

1. **Given** 建筑燃料 48 小时后耗尽, **When** 请求 72 小时预警, **Then** 返回该建筑及剩余时长
2. **Given** 建筑燃料 100 小时后耗尽, **When** 请求 72 小时预警, **Then** 不返回该建筑
3. **Given** 建筑燃料到期时间为空, **When** 请求预警, **Then** 返回该建筑并标记为无燃料数据
4. **Given** 预警时长参数超出合理范围, **When** 请求预警, **Then** 拒绝并提示合法范围

---

### User Story 4 - 查看建筑服务状态 (Priority: P2)

作为军团管理者,我想查看某栋建筑启用的服务及其运行状态(如市场、克隆舱、停泊服务等是否在线),以便确认建筑功能可用性。

**Why this priority**: 服务状态影响建筑功能可用性,是详情的延伸查询,优先级次之。

**Independent Test**: 给定建筑含已启用服务,请求服务状态接口,可返回服务名与状态列表。

**Acceptance Scenarios**:

1. **Given** 建筑含市场与克隆服务, **When** 请求服务状态, **Then** 返回 [{市场, 在线}, {克隆, 在线}]
2. **Given** 建筑服务数据损坏或为空, **When** 请求服务状态, **Then** 返回空列表且不报错
3. **Given** 建筑不属于当前军团, **When** 请求服务状态, **Then** 拒绝访问

---

### User Story 5 - 统计概览 (Priority: P3)

作为军团管理者,我想看到军团建筑的统计概览(总数、各状态数量、即将缺油数量),以便快速评估建筑整体健康度。

**Why this priority**: 概览是辅助决策的聚合视图,优先级低于具体数据查询。

**Independent Test**: 给定军团有 N 栋建筑,请求概览接口,可返回总数 N 及状态分布与预警数。

**Acceptance Scenarios**:

1. **Given** 军团有 10 栋建筑分布在不同状态, **When** 请求概览, **Then** 返回总数 10 及各状态计数
2. **Given** 其中 3 栋即将缺油, **When** 请求概览, **Then** 预警数为 3
3. **Given** 用户不属于该军团, **When** 请求概览, **Then** 拒绝访问

---

### User Story 6 - 增强/解锚时间提醒 (Priority: P3)

作为军团管理者,我想看到处于增强窗口或即将解锚的建筑及其时间节点,以便安排防御或重新锚定操作。

**Why this priority**: 战时与部署场景重要,但日常使用低频,优先级最低。

**Independent Test**: 给定建筑处于增强状态,请求时间提醒接口,可返回该建筑及增强窗口时间。

**Acceptance Scenarios**:

1. **Given** 建筑状态计时结束时间不为空, **When** 请求时间提醒, **Then** 返回该建筑及状态计时
2. **Given** 建筑解锚时间在未来, **When** 请求时间提醒, **Then** 返回该建筑及解锚时间
3. **Given** 建筑无任何计时与解锚时间, **When** 请求时间提醒, **Then** 不返回该建筑
4. **Given** 用户不属于该军团, **When** 请求时间提醒, **Then** 拒绝访问

---

### Edge Cases

- 请求不属于自己军团的建筑或军团资源:拒绝访问(fail-closed,不泄露存在性)
- 军团标识非数字或超长:参数校验拒绝,不下推查询
- 排序字段非法:使用默认排序或拒绝,不接受任意字段
- 服务数据为损坏的结构化文本:返回空列表并记录警告,不阻断详情展示
- 星系名数据缺失:星系名留空,降级显示星系标识
- 燃料到期时间为空:预警接口包含并标记,详情正常显示
- 分页参数越界(页码<1 或每页>上限):校验并限制在合法范围
- 预警时长越界(<=0 或过大):拒绝并提示合法范围

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供分页查询军团建筑列表的接口,返回建筑标识、名称、类型名、星系名、状态、燃料到期时间
- **FR-002**: 系统 MUST 支持按建筑名称模糊筛选
- **FR-003**: 系统 MUST 支持按建筑状态筛选
- **FR-004**: 系统 MUST 支持按燃料到期时间、名称、状态、建筑标识排序,且排序字段限定在白名单内
- **FR-005**: 系统 MUST 提供查询单建筑详情的接口,返回全部建筑字段及已解析的服务列表
- **FR-006**: 系统 MUST 提供查询燃料即将耗尽建筑列表的接口,支持指定预警时长(小时),返回每栋建筑的剩余时长
- **FR-007**: 系统 MUST 提供查询单建筑服务状态的独立接口,返回服务名与状态列表
- **FR-008**: 系统 MUST 提供建筑统计概览接口,返回总数、各状态计数、即将缺油数
- **FR-009**: 系统 MUST 提供增强/解锚时间提醒接口,返回处于增强窗口或即将解锚的建筑及时间节点
- **FR-010**: 系统 MUST 校验请求者对目标军团资源的所有权,非本人军团一律拒绝访问
- **FR-011**: 系统 MUST 在单建筑查询时校验建筑归属请求军团,不属于则拒绝
- **FR-012**: 系统 MUST NOT 提供任何新增、编辑、删除建筑的接口(只读)
- **FR-013**: 系统 MUST 仅读取已同步的本地数据,不在查询时调用外部游戏数据接口
- **FR-014**: 系统 MUST 对损坏服务数据容错,返回空列表而非报错
- **FR-015**: 系统 MUST 对排序字段做白名单校验,拒绝非白名单字段以防注入
- **FR-016**: 系统 MUST 对分页与预警时长参数做范围校验

### Key Entities *(include if feature involves data)*

- **建筑(Structure)**: 军团拥有的太空建筑。属性:建筑标识、名称、所属军团、类型、所在星系、状态、燃料到期时间、增强小时、下次增强时间、状态计时(开始/结束)、解锚时间、服务列表
- **建筑服务(Structure Service)**: 建筑启用的服务。属性:服务名、运行状态(如在线/离线)
- **军团(Corporation)**: 建筑所有者;请求者通过其名下角色所属军团访问该军团建筑

## Success Criteria *(mandatory)*

### Performance Criteria

- **SC-001**: 所有查询接口 95% 分位响应时间在 200ms 以内
- **SC-002**: 单次列表查询在数据层一次性完成关联名称解析,不产生逐条名称回查
- **SC-003**: 统计概览以聚合方式一次获取,不拉取全量逐条计算

### Code Quality Criteria

- **SC-004**: 新增代码单元测试覆盖率 ≥80%
- **SC-005**: 越权访问(非本人军团、他团建筑)场景 100% 覆盖测试
- **SC-006**: 查询输入参数化与排序白名单通过安全评审,无注入风险
- **SC-007**: 代码复杂度低于既定阈值,函数聚焦

### Measurable Outcomes

- **SC-008**: 用户可在 3 秒内浏览建筑清单并定位到目标建筑
- **SC-009**: 用户可一键查看即将缺油建筑并获知剩余时长,避免建筑因燃料耗尽离线
- **SC-010**: 非本人军团的访问尝试 100% 被拒绝,无任何数据泄露

## Assumptions

- 建筑数据已由现有定时任务从 ESI(EVE Online 官方数据接口,领域术语)同步入库,查询接口只读已同步的本地数据
- 请求者已通过项目现有认证体系登录,其角色与军团归属可由现有体系解析
- 物品类型名可通过现有物品类型数据解析;星系名可能部分缺失,缺失时降级显示星系标识
- 建筑状态取值遵循游戏约定(anchor_fuel/low_power/shield_vulnerable/armor_vulnerable/hull_vulnerable/anchoring/unanchoring 等)
- 服务列表在已同步数据中以结构化文本形式存储,展示时需解析为服务名+状态列表
- 国服时区为 UTC+8,燃料预警时间窗沿用现有查询的时区处理方式
- 燃料预警默认时长 72 小时,可由请求参数调整,合法范围为 1~720 小时
- 现有领域实体、仓储、ESI 模型与数据同步定时任务保持不变,本功能仅新增只读查询能力
